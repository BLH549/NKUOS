**补充追问：**

```text
你再去确认Lab1手册 和 /home/liu/projects/nku-os/ 操作系统实验指导书.txt
为什么在我的环境，这个代码需要做这样额外的修改？
```

**排查过程与结果：**

1. 对照 Lab1 手册与教师文本，确认两者都使用 `-device loader`，本项目调整的是 Makefile 的 `qemu`、`debug` 启动参数，不是编译规则。
2. 在 AI 辅助下构建镜像并自动执行同镜像对照：`loader` 方式显示 OpenSBI，但 `Next Address` 为 `0x0`，没有内核输出；`-kernel` 方式显示 `0x80200000`，并打印 `(THU.CST) os is loading ...`。两次都由超时结束，退出码均为 124，判断依据是入口地址与输出。
3. 核对本机默认固件与上游源码：旧 QEMU 4.1.1 的默认 `fw_jump` 固件预设跳转位置；本机 QEMU 7.0.0 默认使用 `fw_dynamic`，需要前一阶段传入内核入口。`loader` 将镜像放入内存，但当前命令没有向 virt 启动流程提供内核入口；`-kernel` 同时完成加载和入口传递。
4. 因此，在保留本机现有默认固件和启动配置时，原命令无法进入内核，现有 `-kernel` 调整有实际依据。它属于环境适配，并非手册要求的内核开发，也不是所有环境都必须做的修改。旧版本机制来自源码核对，本机未重装旧版进行对照。

本次没有新增 Makefile 修改。完整解释与源码依据见 [交接文档的 QEMU 问题](A-构建链接交接.md#qemu)，实测证据见 [对照汇总](evidence/boot-parameters-20261011/summary.json)、[原命令日志](evidence/boot-parameters-20261011/loader.log) 和 [调整后日志](evidence/boot-parameters-20261011/kernel.log)。
