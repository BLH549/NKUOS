### 整体流程与核心代码

```text
构建：.c/.S → 编译、汇编为 .o → 按 kernel.ld 链接为 bin/kernel
      → objcopy 转成 bin/ucore.img

运行：QEMU 预加载固件和内核 → 复位代码 → OpenSBI
      → kern_entry → 设置 SP → kern_init → 清零、输出 → 无限循环
```

`bin/kernel` 保留 ELF 符号和调试信息供 GDB 使用；`bin/ucore.img` 是当前 QEMU 启动命令加载的裸镜像。链接脚本安排地址，运行配置必须与其配合。`ENTRY(kern_entry)` 设置 ELF 入口，实际入口是否在镜像开头还需结合段布局核对。

| 核心文件 | 在流程中的作用 |
|---|---|
| `Makefile`、`tools/kernel.ld` | 构建镜像并安排入口和内存布局 |
| `kern/init/entry.S` | 设置内核栈指针并转入 C 函数 |
| `kern/init/init.c` | `kern_init` 清理 BSS，打印启动消息，进入无限循环 |
| `kern/libs/stdio.c`、`libs/printfmt.c` | 处理格式字符串并逐字符输出 |
| `kern/driver/console.c`、`libs/sbi.c` | 将字符输出请求交给 OpenSBI |

先准备栈，才能可靠地执行需要栈的 C 函数。输出路径为 `cprintf → vcprintf → vprintfmt → cputch → cons_putc → sbi_console_putchar → sbi_call/ecall`，由 OpenSBI 处理底层控制台服务；这是已有代码的功能关系，编译优化可能内联其中部分函数。

## 3. 练习 1：理解内核启动中的程序入口操作

**主笔：B，姓名学号待填写。全员学习并操作验证。**

### 题目

阅读 `kern/init/entry.S`，结合内核启动流程，说明 `la sp, bootstacktop` 和 `tail kern_init` 分别完成什么操作，目的是什么。

### 分析与回答草稿

```asm
kern_entry:
    la sp, bootstacktop
    tail kern_init
```

`la sp, bootstacktop` 将栈顶符号的地址写入 SP，使内核使用自己的启动栈。栈空间已经由 `.space KSTACKSIZE` 静态预留，当前源码定义为两页、共 8192 字节；这条指令设置指针，不在运行时申请空间，也不是读取栈顶地址中的数据。栈向低地址增长，初始 SP 指向预留区末端，为 C 函数保存寄存器、使用局部变量等操作准备环境。

`tail kern_init` 以尾调用方式转移到 C 初始化函数，不为本次跳转在 RA 中创建新的返回地址。`kern_init` 声明为 `noreturn`，完成初始化和输出后进入无限循环，入口无需保留普通调用的返回路径。`la` 和 `tail` 都是伪指令，实际机器指令应以本次反汇编为准。

`kern_init` 中的 `memset(edata, 0, end - edata)` 清理链接符号之间的 BSS 区域，再打印消息。此处作为进入 C 后的简要说明；应检查本次 `edata` 与 `end`，不能假设 BSS 一定非空。

## 6. 总结与答辩准备

### 与操作系统原理的联系

| 本实验知识 | 含义及与原理的联系、差异 |
|---|---|
| 链接与装载 | 链接安排符号地址，装载把字节放入内存；本实验未实现虚拟内存管理 |
| 启动与特权级 | 固件建立底层环境并交给内核，内核通过 SBI 使用固件服务 |
| 栈与函数调用 | 入口建立启动栈，为 C 代码提供运行条件；尚无多进程内核栈管理 |
| 调试与控制流 | 用 PC、反汇编和断点观察实际执行，将源码解释与运行行为对应 |

本实验尚未实现进程调度、页表与地址空间隔离、动态内存管理、文件系统、中断处理和并发同步等重要 OS 功能。
