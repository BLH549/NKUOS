## 物理内存初始化

输入为 `dtb_init()` 保存的单段 RAM 起点和大小。本框架的 `nbase`、链接地址和启动映射均以 `DRAM_BASE=0x80000000` 为基准，所以起点不匹配、大小为零、加法溢出或没有容纳内核与描述符的空间时必须 panic，不能默默使用硬编码内存大小。

`va_pa_offset=PHYSICAL_MEMORY_OFFSET`；管理上界取 DTB RAM 末尾与 `PHYSICAL_MEMORY_END` 的较小值，再向下对齐到 4 KiB。`npage` 是绝对物理页号的上界，数组长度是 `npage-nbase`。

描述符数组从 `ROUNDUP(end, PGSIZE)` 开始，并且必须完整落在可管理 RAM 内。初始化每个描述符的标志、引用计数、块大小及链表指针，所有页先标记保留。从数组末尾向上对齐后的第一完整页开始，才交给当前管理器。固件、内核、启动栈、启动页表及描述符存储页均不释放；完整可用页数为零时不调用 `init_memmap()`。

范围日志采用左闭右开区间。当前起始 DTB 解析器只支持首个 memory 节点的一组 64 位地址/长度，不承诺通用多 RAM bank 或任意 reserved-memory 布局；报告须说明这一边界。

## Best-Fit

遵守 `pmm_manager` 和现有 `struct Page`，不修改公共结构。空闲链表按物理地址递增，每个块只有首页带 `PG_property`，`property` 为连续空闲页数，`nr_free` 为所有空闲块页数之和。

分配扫描全部足够大的块并选最小者，相同大小选择低地址，精确匹配可立即停止。只返回恰好 n 页，剩余块留在原地址顺序位置；失败返回 NULL 且不改变状态。n=0 沿用原框架 assert 契约。

初始化和释放均按地址插入并合并紧邻前后块，清除被吸收块的首页标志，恢复引用计数与总页数。不接收保留页或已空闲的块。保持原始 `basic_check()`、`best_fit_check()` 文本不变。

默认管理器为 Best-Fit，通过 `make PMM=first_fit` 切换 First-Fit；切换时必须触发管理器选择代码重编译。B 后续可在同一选择入口追加 Buddy。
