## 1. 共享接口与集成范围

- 沿用 A 的物理内存初始化及 `pmm_manager`，不修改 `struct Page` 布局、First-Fit/Best-Fit 源码和原始检查函数。
- 增加 `make PMM=buddy`；默认仍为 Best-Fit。管理器切换沿用已有配置标记机制。
- `pmm.c` 仅增加 Buddy 头文件及选择分支；在 `kern_init()` 的 `pmm_init()` 后初始化并检查 SLUB。
- 本实现用于实验的单 hart 顺序调用；不提供并发、关中断保护、NUMA 或每 CPU 缓存。若之后由中断或多 hart 调用，必须先补同步。

## 2. Buddy

### 接口和状态

实现 `init/init_memmap/alloc_pages/free_pages/nr_free_pages/check`。阶数范围 0～15；阶 k 的块包含 `2^k` 个 4 KiB 页面。上限与框架最大管理的 128 MiB 相容。

`free_lists[k]` 保存 k 阶空闲块。空闲块首页设置 `PG_property`，`property=k`，其中 k=0 同样有效，不能用 `property!=0` 判断空闲。内部页不在空闲链表中。

使用 `Page.flags` 原先未使用的 bit 2、bit 3 分别记录已分配块首页、尾页。首页 `property` 记录原请求 n，避免把请求大小与实际块大小混淆；不改变公共结构大小。其他管理器只管理各自初始化后的状态。

### 地址、初始化与合并

以绝对物理页号为基准。k 阶块首页满足 `page2ppn(base) % (1UL<<k)==0`，伙伴页号为 `page2ppn(base) ^ (1UL<<k)`，不能对 `Page *` 指针值异或。

注册任意非空的保留页区间，按“当前页号对齐且不超过剩余长度”的最大阶切分。所有描述符先清理，随后逐块插入；支持非对齐起点、非 2 的幂长度、多次注册、空洞和乱序注册。

合并必须同时满足：伙伴位于描述符范围内、伙伴是空闲块首页、阶数相同。由两块较低地址作为新首页，逐级递归合并，不能因为地址相邻就合并。已保留页和区间外页面不可进入分配范围。

### 请求与释放

- `alloc_pages(n)` 返回至少 n 页的连续物理块，实际占用 `round_pow2(n)` 页。
- n=0、n>32768、没有足够阶数块时返回 NULL；状态与页数不变，大小上限检查必须先于取整以防溢出。
- `free_pages(p,n)` 必须传入分配时的首页和原始请求 n。例如申请 3 页占用 4 页，应调用 `free_pages(p,3)`。
- 校验首页标志、原请求、对齐、尾页状态及边界后，才清理元数据并归还整个取整块。错误大小、内部页释放、重复释放均触发断言。
- 空闲页数按真实占用页数增减。允许因为碎片而“空闲页总数足够但没有满足请求的块”。

## 3. 简化 SLUB

接口为 `slub_init()`、`slub_alloc(size)`、`bool slub_free(void *)`、`slub_check()`。

底层通过选中的 PMM 分配/归还单页，因而与 Buddy 的 n=1 契约一致，也可运行在 First-Fit、Best-Fit 上。类别为 16、32、64、128、256、512、1024、2048 字节；支持 1～2048 字节请求并向上归类，所有对象至少 16 字节对齐。请求 0 或超过 2048 返回 NULL，不支持大对象跨页分配。

每个 slab 占一页，页首保存页描述符、类别、使用数、容量、4 个 64 位位图和链表节点；数据区起点按 16 字节对齐。容量为 `(PGSIZE-header_aligned)/class_size`。每类分为 partial/full 两条链，分配时优先使用 partial，满页转入 full；回收满页中的对象后转回 partial，页空时立即归还 PMM，不缓存空页。

释放时先按页对齐得到候选页，再扫描拥有的 partial/full 链表，找到已知 slab 后才读取它的元数据；验证对象起点、索引和使用位。NULL 返回 true；非法地址、对象内部指针、未分配槽位和未被重新分配的重复释放返回 false，不改变状态。不能检测“某个旧地址恰好已重新分配给另一个对象”的悬空指针，不承诺通用内存安全。

该模块展示页层与对象层分离、类别缓存和 slab 状态迁移；采用位图与链表扫描，没有复现 Linux SLUB 的每 CPU freelist 等全部机制。

## 4. 验证约定

1. 内核中运行 Buddy 的取整、对齐、不重叠、计数、失败请求和乱序释放检查。
2. 主机直接编译真实 Buddy 源码，独立位图逐页跟踪状态，并扫描所有对齐候选区间判断请求是否应成功；不以 Buddy 链表作为测试预期。
3. 覆盖 63 页非对齐区域、耗尽、跨阶拆分与合并、相邻非伙伴不合并、乱序区间注册、保留空洞以及 20,000 次随机操作。
4. 错误大小、尾页释放和重复释放在独立进程中验证预期 panic。
5. SLUB 内核检查类别边界、对齐、数据独立、多个 slab、释放复用、非法输入与页数恢复；主机在三种 PMM 上各执行 5,000 次随机对象操作并模拟底层耗尽。
6. 主机启用 ASan/UBSan；QEMU 实际运行三种 PMM，Buddy 另测 64/128/256 MiB。教师评分仅作为 A 部分及集成回归证据，不能代替 B 的测试。
