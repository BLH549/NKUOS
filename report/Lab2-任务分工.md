## 2. 共同理解的实验主线

```text
entry.S 建立启动映射、开启 Sv39 分页
    ↓
kern_init() 读取设备树中的内存信息
    ↓
pmm_init()
    ├─ init_pmm_manager()：选择并初始化页分配器
    ├─ page_init()：安排 Page 描述符、排除保留区域
    │      └─ init_memmap()：向当前分配器注册空闲页
    └─ check_alloc_page()：检查当前页分配器
    ↓
分别验证 First-Fit、Best-Fit 和 Buddy
    ↓
在页分配接口上建立 SLUB 对象分配
```

QEMU 调试分支从模拟器内部观察虚拟地址翻译、页表遍历和 TLB 行为，与上述分配任务相互补充。

三人均需理解虚拟地址、物理地址、页号与 `Page *` 的区别，以及 `struct pmm_manager` 的接口职责。每人至少亲自运行一次完整实验流程，并能解释自己的任务和公共主线。

## 6. 协作顺序与接口约定

### 阶段一：并行准备

- A 优先完成 `page_init()`，使用现有 First-Fit 交付可运行基线。
- B 阅读 `pmm_manager`、页描述符和链表接口，设计 Buddy 与测试方案。
- C 准备调试版 QEMU，阅读地址翻译源码，搭建 GDB 环境。

### 阶段二：各自实现与验证

- A 基于初始化基线完成 Best-Fit 与思考题。
- B 基于初始化基线完成 Buddy，再完成 SLUB。
- C 基于可运行内核完成页表和 TLB 调试。

### 阶段三：整合与交叉检查

- A 整合代码，分别运行各分配器及 SLUB 的验证，整理最终测试结果。
- B 汇总三人的知识点材料，检查实验实现与 OS 原理之间的对应关系。
- C 整合报告与截图，核对所有练习、Challenge 和调试要求是否有对应内容。
- 三人交叉阅读其他模块，准备完整流程演示和答辩。

### 共享接口与文件

1. `pmm.c` 中的初始化和管理器选择由 A 统一整合；B 提供 Buddy 注册结构及切换需求。
2. A、B 在实现前约定管理器选择方式；First-Fit、Best-Fit、Buddy 应能分别验证，记录各自使用的配置和结果。
3. B 明确 Buddy 的请求与释放语义，并确保 SLUB 的底层调用与其一致。
4. 如需修改 `struct Page`、`pmm.h`、`memlayout.h` 等公共定义，先同步影响，再由 A 整合。
5. C 对 Makefile、QEMU 路径或 GDB 配置的调整需记录清楚；最终保留他人可复现的配置方式。
6. Best-Fit 现有两个测试函数不得修改；Buddy 和 SLUB 使用各自新增的测试。
