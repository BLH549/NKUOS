# Lab3 运行与 A 的调试

本次验证环境为 WSL2 Ubuntu 24.04.4、RISC-V GCC 13.2.0、QEMU 8.2.2 和 gdb-multiarch 15.1。版本记录见 [environment.json](../evidence/A-20261104/environment.json)。

## 构建与启动

在仓库根目录进入 WSL，再执行：

```bash
cd code
make
make qemu
```

Makefile 默认使用 `rv64imac_zicsr_zifencei` 和 `lp64`。启动后输出 Best-Fit 自检成功和时钟初始化信息。当前时钟处理函数为空，后续重设、输出和关机由该函数完成。退出 QEMU 时按 Ctrl+A，松开后按 X。

## A 的自动验证

```bash
make check-a
```

验证脚本在临时副本中加入四个异常触发点、两个最小处理桩和结束标记，由 GDB 逐次检查保存帧和返回状态。结果默认写入 `report/evidence/A-20261104/`，可指定其他目录：

```bash
python3 tools/check_a.py --output ../report/evidence/A-recheck
```

通过时输出：

```text
PASS: frame layout, 32 registers, 4 exceptions, 3 timer returns, S privilege
```

`trap-gdb.log` 记录断点与逐项检查结果，`trap-summary.json` 汇总七次 Trap 的帧地址、epc 和返回特权级。触发点编码见 `fixture-disassembly.log`；启动、计数完成和后续标记的串口输出见 `fixture-qemu.log`。`tested-source.json` 保存所测 `trapentry.S` 的 SHA-256。

## 手动观察共同入口

终端一：

```bash
make debug
```

终端二：

```bash
make gdb
```

连接后执行：

```gdb
hbreak *kern_init
continue
delete breakpoints
hbreak *__alltraps
hbreak *trap
hbreak *__trapret
continue
info registers sp ra a0 sstatus sepc scause stval
continue
p/x $a0
p/x $sp
p *(struct trapframe *)$a0
p sizeof(struct trapframe)
continue
info registers sp
x/36gx $sp
disassemble __trapret
```

`__alltraps` 断点位于 `SAVE_ALL` 前，此处记录原 sp。到达 `trap` 第一条指令时，a0 和 sp 应相等，均比原 sp 小 288；到达 `__trapret` 时，sp 应重新指向帧首。恢复末尾从第 2 槽取回原 sp，随后执行 `sret`。在帧内 `epc` 指向的位置设置临时硬件断点，可继续核对返回后的 PC 和 `$priv`。

## 处理函数与整体验证

两个处理函数位于 `kern/trap/trap.c` 的 `lab3 function2` 区域，通过已有 `trap_dispatch()` 分发。当前框架定义 `TICK_NUM=100`，提供 `clock_set_next_event()`、`ticks` 和 `sbi_shutdown()`；`SHUTDOWN_AFTER` 需要在处理区域中补充。实现范围按原分工文档执行。

处理函数完成后，依次运行 `make`、`make qemu` 和 `make grade`。评分脚本包含上下文恢复与断点返回、非法指令返回、连续时钟中断三组检查。独立验证用于检查保存与恢复路径，整体验证进一步检查正式输出、计数边界和关机行为。
